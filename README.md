1. DDA Line & Bresenham’s Circle RasterizationThe Digital Differential Analyzer (DDA) algorithm plots straight lines by calculating differential coordinate steps ($\Delta x$ or $\Delta y$) along the line's driving axis, incrementally adding the slope $m$ to determine each successive point before rounding to the nearest integer pixel. Meanwhile, Bresenham’s Circle Algorithm avoids floating-point arithmetic and trigonometric functions by tracking an integer decision parameter ($d$) derived from the midpoint between candidate pixels. It calculates points for a single octant and mirrors them across the remaining seven octants using 8-way symmetry, yielding fast, accurate primitive rasterization for complex graphical patterns.

2. Cohen–Sutherland Line Clipping AlgorithmThe Cohen–Sutherland algorithm prevents rendering off-screen primitives by dividing the 2D plane into nine zones around a rectangular clipping window ($x_{min}, x_{max}, y_{min}, y_{max}$) using 4-bit Outcodes (Top, Bottom, Right, Left). Lines with both endpoint codes equal to 0000 are trivially accepted, while lines sharing an exterior bit (code1 & code2 != 0) are trivially rejected. Any line spanning across boundaries is iteratively clipped by calculating its exact slope intersection with the window edge, updating the exterior endpoint until the remaining segment is either accepted or discarded.

3. 2D Geometric Transformations2D transformations alter an object's spatial coordinates $(x, y)$ to $(x', y')$ through translation, scaling, rotation, reflection, and shearing. By adopting homogeneous coordinates ($[x, y, 1]$), affine transformations—which normally require vector addition—are unified with linear transformations into $3 \times 3$ matrices. This allows multiple operations to be combined into a single composite matrix via matrix multiplication ($P' = M \cdot P$), enabling efficient pivot-point manipulations and arbitrary reorientations without recomputing individual vertices at each stage.

4. Scan Line Polygon Filling AlgorithmThe Scan Line algorithm fills arbitrary and concave polygons by sweeping an imaginary horizontal line across the polygon's bounding box and pairing boundary crossings to fill the interior spans between them. It pre-sorts non-horizontal edges by their minimum $y$-coordinate into an Edge Table (ET) and dynamically maintains an Active Edge Table (AET) sorted by current $x$-intersections for the current scan line. Applying parity (even-odd) rules between pairs of sorted intersections, it turns on pixels between consecutive edges and increments $x$-coordinates for the next scan line via the edge's inverse slope ($1/m$).
